# OrdreTitre — Suivi des Audiences & Délibérés

A legal case-management application for **Afriland First Bank's legal department**. It tracks judicial cases (*dossiers*), their hearings (*audiences*) and rulings (*délibérés*), the lawyers and internal agents in charge, and lawyers' fees. It raises alerts on hearings and appeal deadlines, and produces management reports.

It is a **Power Apps Code App**: a React single-page app hosted by the Microsoft Power Platform player, with data in SharePoint lists (or Dataverse). There is no custom backend server.

> The repository and package are named `OrdreTitre(s)`; inside the app, the title is **"AFB — Suivi des Audiences & Délibérés"**.

## Features

- **Dashboard**: active cases, planned hearings, expected rulings, pending alerts, recent cases and upcoming hearings.
- **Cases (*dossiers*)**: create, list, search and open a case with its parties, attached documents (*pièces*), nature of procedure (criminal, labour, civil, commercial, arbitration…), amount at stake, risk level and status (open, in progress, under deliberation, closed, archived).
- **Hearings (*audiences*)**: planning and follow-up of scheduled and held hearings.
- **Rulings (*délibérés*)**: expected date, result, and the available appeal routes with their deadlines.
- **Stakeholders (*intervenants*)**: external lawyers (with a maximum caseload) and internal agents.
- **Fees (*honoraires*)**: lawyers' invoices, with a validation and payment workflow.
- **Courts (*juridictions*)** and an internal **case-law (*jurisprudence*)** reference.
- **Alerts**: derived live from the data, never stored. Seven triggers: hearing reminders (D-7, D-3, D-1, D-0), appeal deadlines (D-30 to D-0), ruling expected but not recorded, incomplete case file, unpaid fees, lawyer over their caseload limit, and case inactivity (off by default). E-mails are composed through `mailto:`, so no secret or mail server is needed.
- **Reports** with Excel and PDF export: litigation provisions by risk level, appeal deadlines, file completeness and traceability, duplicates and lawyer workload, immobilisation rate, and internal case law.
- **Import / export**: Excel and CSV import dialogs for each entity, with generators for test import files.
- **Global search** and a notification bell.
- **Audit log**: append-only record of every change.
- **Users and access control**: five roles (Administrator, Supervisor, Legal officer, Reader, External lawyer) and an **editable permission matrix** of 16 permissions (page "Rôles & permissions", admin only).

## Architecture

- **A single data-access interface** (`src/data/source.ts`) with four implementations, chosen by the `DATA_SOURCE` constant:

  | Value | Behaviour |
  |---|---|
  | `'seed'` | Local demo data (default). Nothing to configure |
  | `'sharepoint'` | Every entity on SharePoint lists |
  | `'sharepoint-audiences'` | Hybrid: hearings from SharePoint, the rest from seed (a validation step before a full switch) |
  | `'dataverse'` | Dataverse tables |

- **Authentication.** In production the user is already signed in with their Microsoft account; the app reads that identity through the SDK and maps it, by e-mail, to a user record to find their role. Outside the Power Apps player there is a demo sign-in form that accepts any password, which is why it must never be used with real data.
- **Alerts are derived, not stored** (`src/alertes-engine.ts`). Only "read" and "dismissed" states are kept.
- **Bundling.** Small assets are inlined, and the PDF and Excel libraries are split into their own chunks to keep the main bundle and build memory low.

## Getting started

**Prerequisites:** a current Node.js LTS (20.19 or newer) and npm.

```bash
npm install
npm run dev        # Vite dev server (runs on the local seed data)
```

| Command | What it does |
|---|---|
| `npm run dev` | Start the dev server |
| `npm run build` | Type-check and build into `dist/` |
| `npm run preview` | Preview the production build |
| `npm run lint` | Lint with ESLint |
| `npm run generate-test-import` | Generate `.xlsx` files filled with realistic sample data (written to `generated-test-imports/`) to try the import dialogs. Add a suffix for one entity: `:audiences`, `:dossiers`, `:honoraires`, `:deliberes`, `:avocats`, `:agents`, `:juridictions` |

**Deploying** to a Power Platform environment:

```bash
npm run build
pac code push
```

## Connecting real data

The app ships on seed data. To switch to real data, follow the step-by-step guides (in French):

- [`SHAREPOINT.md`](./SHAREPOINT.md): create the 13 SharePoint lists from the CSV files, add them as data sources with `pac code add-data-source`, then set `DATA_SOURCE`.
- [`DATAVERSE.md`](./DATAVERSE.md): create the Dataverse tables and wire them in.
- [`csv/README.md`](./csv/README.md): the 13 reference CSV files (one per entity), their columns and formats. Regenerate them after changing the seed with `node scripts/export-csv.mjs`.

Helper scripts in [`scripts/`](./scripts): `pac-init.ps1` (wraps `pac code init` using `power.config.json`), `add-sharepoint-sources.ps1` (generates the typed services for the SharePoint lists), `export-csv.mjs` and `generate-test-import.ts`.

## Project structure

```
src/
  pages/          one screen per file: dashboard, dossiers, audiences, délibérés, honoraires, reports, audit…
  components/     reusable UI: dialogs, pagination, searchable select, global search, notification bell
  layouts/        application shell
  data/           data-access layer: store, seed data and the SharePoint / Dataverse sources
  generated/      typed models and services generated by pac code (do not edit by hand)
  lib/            import, export, reports, statistics, e-mail notifications and test-data generators
  alertes-engine.ts   alert rules
  auth.tsx, rbac.tsx  sign-in and the editable permission matrix
csv/              seed / reference data, one CSV per entity
scripts/          PowerShell and Node helper scripts
power.config.json Power Apps app and data-source configuration
```

Other documentation: [`documentation.md`](./documentation.md) (general project notes).
